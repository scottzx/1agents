# WorkBuddy 前端交互参照 + 1agents 整体交互重构建议

**Date:** 2026-06-29
**Scope:** 前端 IA / 交互设计;支撑 [agentsOS 架构设计](../agentsOS-架构设计.md) §2 分层、§7 项目外壳、§8 应用挂载点

> 现状:我们有**内核**(执行/任务/项目三层)+ **外展**(应用,如 CRM),整体偏复杂,交互需要重新设计,让用户不被复杂度淹没。本文先记录 WorkBuddy 的交互范式作参照,再给我们的重构建议。

## 1. WorkBuddy 前端交互参照(四屏实测)

WorkBuddy v5.1.7,与我们形态接近,可借鉴。

### 1.1 左栏 L1 导航
`新建任务` · `助理` · `项目` · `专家(技能·连接器)` · `自动化` · `更多(资料库·灵感)`;下方 **空间**:`项目新手指引`(项目)、`wechat_articles`(普通文件夹)。底部:用户头像 + 通知 + 设置。

### 1.2 助理(默认会话,绑工作目录)
- 一个**绑定工作目录**的默认会话(实测 `pwd = /Users/scott/WorkBuddy/Claw`);助理项右侧有 **文件夹 + 齿轮** 图标(选目录 / 配置)。
- 顶部"已连接:微信小程序";聊天区底部工具条:`Craft · 自动 · 技能 · 工具 · 默认权限`。
- **要点:对话即派活,且对话有明确的工作目录上下文。**

### 1.3 新建任务(home 落地页)
- 大标题"WorkBuddy·你的职场超能力";模式切换 `日常办公 / 代码开发 / 设计创意`;场景快捷入口 `文档处理 / 金融服务 / 高考我帮你 / 更多`;聊天输入框 + 底部 **「选择工作空间」**。
- **要点:home 用场景化入口降低"我能拿它干嘛"的门槛 + 一次性对话可挑工作空间。**

### 1.4 项目列表
- "多人协同打造超级团队";`新建项目`;`我的项目`(卡片);**从模版创建**:`产品需求全流程 / 市场调研与竞品分析 / 团队知识库 / 项目交付 / Bug 跟踪`。
- **要点:专业项目从模板创建;模板 = 预置好一套配置/流程的项目骨架。**

### 1.5 项目详情(共享外壳 + 项目配置)
- 主标签:**`动态 / 计划 / 任务 / 资产`**;右侧 **「项目配置」** 面板:`指令 / 连接器 / 专家 / 技能 / 自动化`(每项可 +);右上 `邀请`。
- 动态流:`BuddyBot 创建了事项并指派了你 · 邀请队友 / 上传资料 / 新建任务问 Agent …`。
- **要点:所有专业项目共享一套外壳(动态/计划/任务/资产);项目配置 = 该项目的 agent 上下文。**

### 1.6 值得借鉴的点(对照我们)
| WorkBuddy | 对应我们的概念 |
|---|---|
| 助理(绑 cwd 的默认会话) | 三层会话入口之"助理"(默认 workspace) |
| 普通文件夹(wechat_articles) | "通用项目"(选文件夹直接对话,不挂应用) |
| 项目(从模板创建) | "专业项目"(选模板 = 领域应用) |
| 项目详情:动态/计划/任务/资产 | **平台级项目外壳**(§7) |
| 项目配置:指令/连接器/专家/技能/自动化 | **项目配置 = 任务的 agent 上下文**(§7) |
| 缺 `function`(确定性)这一维 | 我们的**结构性优势**:加上 function |

## 2. 我们的复杂度问题

内核(执行/任务/项目)+ 外展(应用)叠在一起,容易出现:
- 用户搞不清"助理 / 文件夹 / 项目 / 应用 / 任务台"分别是什么、什么时候用哪个;
- 应用各自一套 UI,彼此割裂;
- 内核术语(executor、business_ref、挂载点)泄漏到用户面,显得抽象难懂。

**目标:渐进暴露复杂度——轻用户只见对话,重场景才见整套。**

## 3. 交互重构建议(IA)

### 3.1 三层会话入口(降低门槛的主线)
| 入口 | 是什么 | 复杂度 |
|---|---|---|
| **助理** | 默认 workspace + 对话,可直接派任务 | 最轻(纯对话) |
| **通用项目** | 选/建一个文件夹直接对话,沉淀文件,**不挂应用、无任务看板** | 轻 |
| **专业项目** | 选模板(= 应用)→ 完整任务管理 + 领域视图 | 重(整套) |

→ **轻用户停在助理/通用项目,重场景才进专业项目。** 用户只需感知"助理 / 项目 / 应用",不必懂"内核/外展"。

### 3.2 L1 导航(业务轨)
`助理` · `项目` · `[已启用应用:CRM …]` · `任务台` · `设置`。
- **应用挂载点**(§8)决定它出现在哪:**项目内 tab**(项目级,如视觉创作)/ **L1 独立页**(全局,如 CRM)/ **项目透视**(横切,如成本)。
- **任务台** = 跨应用的执行总览(内核 ②③④ 的运维镜头);普通用户不常进,power user 用。

### 3.3 共享项目外壳(参照 WorkBuddy)
专业项目统一外壳:**`动态 / 计划 / 任务 / 资产` + 项目配置(指令/连接器/专家/技能/自动化)**;应用只在外壳上**加自定义标签/视图**(如自媒体的"段落取舍"、CRM 的"线索漏斗")。保证一致性、避免每个应用各造一套。

### 3.4 co-pilot 常驻
对话入口随处可唤、随上下文变(在助理 / 在某项目 / 在某对象);说一句话 → 意图识别 → 落成任务。**对话是贯穿三层的主入口,不是第 N 个标签。**

### 3.5 执行态内联
任务/工单状态**内联进业务卡**(如 CRM 决策卡上显示"分析中→完成"、阶段卡上显示 agent/function 进度),而不是让用户切到任务台去看。任务台只作总控镜头。

---

## 4. 重构原则

1. **渐进暴露**:助理 → 通用项目 → 专业项目,复杂度逐级展开;别一上来就甩整套。
2. **术语不泄漏**:用户面只说"助理/项目/应用/任务";executor、business_ref、挂载点是内部词。
3. **一套外壳,应用只加视图**:共享 动态/计划/任务/资产 + 项目配置,应用贡献自定义标签。
4. **执行态就地可见**:状态内联业务卡;任务台是运维镜头,非主路径。
5. **对话贯穿**:co-pilot 常驻,意图即任务。
6. **三角色显式但克制**:agent/function/human 可在任务/阶段卡上以小标识体现("谁在干"),但不要喧宾夺主。
