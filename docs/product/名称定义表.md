### 0.1 实体骨架（裁决版）

```
Workspace（API/类型真名）= Project（产品对外名）
  · 同一 id；目录投影 = workspace path
  · kind ∈ { workforce | project }     ← 落库仅两档
  · UI 文案：kind=workforce →「助理」；kind=project →「项目」

  ├── ProjectItem（表 project_items；原 tasks）
  │     · ItemType ∈ { task | requirement | bug | discussion }
  │     · 仅 ItemType=task 进入 executor 调度
  │     · executor ∈ { agent | function | human }   ← 通道
  │     · assignee = 该通道下的具体对象             ← 对象
  │     · function 通道另保留 function_type 字段
  │
  └── Session（前端/UI 总称）
        ├── ChatSession（表 sessions）
        │     · 长期、可恢复的 Agent 对话容器；可选软关联一个 ProjectItem
        │     └── AgentTurn（表 agent_turns）
        │           · 一次用户提交到明确终态的可审计因果批次
        │           · 可通过 project_events 影响多个 ProjectItem
        └── TerminalSession（tmux window 投影）
              · 终端交互容器；不因命令输入自动创建 AgentTurn
```

### 0.2 ProjectItem / ItemType（原 tasks / TaskType）

| 裁决 | 说明 |
|------|------|
| 表名 | **`project_items`**（逻辑名 ProjectItems；旧表 `tasks` 启动时 rename） |
| 类型名 | Go/TS **`type ProjectItem struct`** 为定义处；**不再**把 Task 当表名或主类型名 |
| 枚举名 | **`ItemType`**；`TaskType` = deprecated alias → 新代码只用 ItemType |
| 枚举值 | 保留 **`task` \| `requirement` \| `bug` \| `discussion`** |
| **强制** | **`task` 只作 ItemType 枚举值**，不是表名、不是主类型名 |
| 可调度 | **仅 `ItemType=task`** 进入 executor 调度；requirement/bug/discussion 为不可执行议题类 |
| 话题语义 | ProjectItem 可带 Description + Replies 时间线（原 issue-model）；`issue_state` 与 workflow `status` 正交 |
| 过渡别名 | Go：`type Task = ProjectItem`；TS：`export type Task = ProjectItem`。**仅兼容旧 import，注释标明删除期限，禁止新代码使用**（#197） |

### 0.3 项目从属（可无 PM 外壳 ≠ 可无存储行）

| 裁决 | 说明 |
|------|------|
| 逻辑 | 可无完整 PM 外壳（无强制里程碑/需求池等）——如 **助理 (workforce)** |
| 存储 | **每条 ProjectItem 始终挂一条 Workspace/Project 行**（含 builtin 助理） |
| 否决 | 「Task 可脱离 Project、schema 无 project_id」——与实现不符，废止 |

### 0.4 Workspace.kind 两档 + 创建向导

| 概念 | 代号 | 说明 |
|------|------|------|
| 落库 kind | **`workforce` \| `project`** | **仅此两档**（已落地） |

### 0.5 executor（通道）× assignee（对象）

| 字段 | 含义 |
|------|------|
| **`executor`** | 三态**通道**：`agent` \| `function` \| `human`（字段名保持 `executor`，不改为 AIWorkforce） |
| **`assignee`** | 该通道下**具体执行对象** |

| 通道 `executor` | `assignee` 填什么 | FunctionType / 标签 |
|-----------------|-------------------|---------------------|
| `agent` | AgentType：`codex` / `claude` / …（**禁止** `user`） | 无 |
| `human` | 暂固定 **`user`**；以后可拓展员工工号 | 无 |
| `function` | **函数注册名**（与 FunctionType 同值镜像） | DispatchSpec / body 的 `functionType`；Labels 写入 `fn:<name>`（`ApplyFnLabel`） |

**唯一校验入口（已落地 · #198）**

| 符号 | 职责 |
|------|------|
| `meta.NormalizeExecutorAssignment` | 矩阵规范化 + 非法组合 error（HTTP 4xx / taskapi error） |

| `taskapi.NormalizeDispatchSpec` | **委托**上述 meta API，不再分叉实现 |
| `POST/PATCH /api/agent/project-items` | 与 taskapi **同一矩阵**（body 可带 `executor` / `functionType`） |

**否决**：

- 把 `executor` 写成唯一「谁来做」而忽略 assignee  
- 把 `executor=agent` 改名为 `AIWorkforce`（与 kind 撞车）  
- 把 Chat 消息角色 `assistant_text` 与 kind/workforce 混称

### 0.10 连接拓扑（Remote Agent · Relay · 渠道）

三条**正交**轴，不可混称：

```
                    ┌── C1 UI（浏览器 / Tauri）
                    │
     接入方式 ──────┼── Direct：C1 → 本机 Go（如 :38080）
                    │
                    └── Relay（happy-server）：C1 ⇄ S ⇄ C2(adapter + Go + ttyd)
                              「远程连到哪台跑 1agents 的机器」

     消息渠道 ────── cc-connect：飞书 / Telegram / Discord / … ⇄ 同一 C2 上的会话/Agent
                              「工作从哪个 IM 进出」—— ≠ Relay

     Remote Agent ── 产品/历史统称：可远程操作的 Agent 工作台形态
                      = Direct 或 Relay 之上的 1agents，可再挂「渠道」
```

| 名称 | 一句话 |
|------|--------|
| **Relay** | 远程到达**哪台电脑**上的 1agents |
| **渠道** | IM/消息从**哪条业务通道**进系统（cc-connect） |
| **Remote Agent** | 整机产品/历史叫法，**不是**第三套协议 |

### 0.11 Session 与 AgentTurn（Turn）边界

#### 权威定义

| 中文名 | 代号 | 定义 | 不是 |
|--------|------|------|------|
| **会话（UI 总称）** | **`Session`** = `ChatSession \| TerminalSession` | Workspace 下可切换交互表面的前端联合类型；具体持久化和生命周期必须区分 Chat 与 Terminal。 | 不是一张统一的 Session 领域表；不能把 Chat 的 Turn 规则套到终端字节流。 |
| **Agent 对话会话** | **`ChatSession`** · `sessions` | 长期、可恢复的 Agent 对话容器，保存 Agent 类型、权限和 runtime resume 身份；生命周期覆盖多个 Turn，可选软关联一个 ProjectItem。本文下文未特别说明时，`session_id` / Turn 所属 Session 均指 ChatSession。 | 不是一次 Prompt；不是一次 TaskRun；不是某个 ProjectItem 的执行记录。 |
| **终端会话** | **`TerminalSession`** · tmux window | Workspace 内终端窗口的 UI 投影，以 tmux window / ttyd 字节流为生命周期；不进入 `agent_turns`。 | 不是 `sessions` 表中的 Agent 对话；终端每条命令不自动等于 Turn。 |
| **Agent Turn / 本轮** | **`AgentTurn`** · `agent_turns` · UI 可简称 Turn | 一次已提交的用户意图，从 Go 接受并创建 canonical `turn_id` 开始，到 `completed` / `failed` / `cancelled` 明确终态结束的可审计因果批次。 | 不是前端按消息顺序猜出的折叠组；不是 Session；不是 ProjectItem；不是 TaskRun；不保存私有思维链。 |

#### 关系与从属

```text
Workspace   1 ── N ChatSession
Workspace   1 ── N TerminalSession
ChatSession 1 ── N AgentTurn

ChatSession N ── 0..1 ProjectItem   （sessions.task_id，可空软关联）
AgentTurn   N ── M ProjectItem      （通过 project_events）
AgentTurn   1 ── 0..N TaskRun       （可选 origin_turn_id）
```

裁决：

- ChatSession 和 TerminalSession 都必须属于一个 Workspace，但只有 ChatSession 进入 `sessions` / AgentTurn 模型。
- ChatSession **不强制**属于某个 ProjectItem；project-wide ChatSession 可以跨多个工作项。
- 一个 Turn 必须且只属于一个 ChatSession 和一个 Workspace；Turn 不跨 Session，也不自动由 TerminalSession 输入产生。
- `sessions.task_id` 只表达会话上下文或权限收窄的单值软关联，**不得**用来表达“一轮影响多个 ProjectItem”。
- Turn 影响的 ProjectItem 由不可变 `project_events.turn_id` 表达；执行尝试由 `task_runs.origin_turn_id` 表达。
- ChatSession 回答“长期 Agent 对话发生在哪里”，Turn 回答“这次用户意图产生了什么结果”，TerminalSession 回答“哪个终端窗口承载字节流”，TaskRun 回答“某个 task 型 ProjectItem 这一次怎样执行”。

#### 身份与幂等

| ID | 生成方 | 作用域 | 裁决 |
|----|--------|--------|------|
| `session_id` | 1agents Go | 一个 ChatSession、多个 Turn | Agent 对话宿主会话 canonical ID；对应 `sessions.id` 和 1acp `acpxRecordId`，不指 tmux window。 |
| `acp_session_id` | Agent / ACP | 多个 Turn | Agent 侧 resume/load 身份；**不等于** `session_id`。 |
| `agent_session_id` | Agent，可选 | 多个 Turn | Agent 原生线程身份；**不等于** `session_id`。 |
| `client_request_id` | Browser | 一次提交及其网络重试 | 只负责提交幂等；映射 `(session_id, client_request_id) → turn_id` 一旦建立永久不变。 |
| `turn_id` | 1agents Go | 一次 Turn | `agent_turns.id`，全链路 canonical Turn ID；Browser 不得指定。 |
| `runtime_request_id` | 直接取 `turn_id` | 一次 runtime Turn | bridge / 1acp 不得另造第二套 request ID。 |
| `prompt_message_id` | 直接取 `turn_id` | SessionRecord transcript | `SessionMessage.User.id`，作为持久化消息边界。 |
| `event_sequence` | bridge/runtime | Turn 内 | 从 1 单调递增，用于重复事件和迟到事件过滤；不是业务 ID。 |

同一 ChatSession 内：

- 相同 `client_request_id`、相同请求指纹：返回同一个 Turn，不重复执行；
- 相同 `client_request_id`、不同请求指纹：`IDEMPOTENCY_CONFLICT`；
- 相同 Prompt 文本、新 `client_request_id`：创建新 Turn；
- 取消或编辑后重新发送：创建新的 Request / Turn；不建立 replace、supersedes 或继承队列位置关系；
- Prompt 文本和 queue position 都不是关联键。

#### 生命周期、队列与终态

```text
queued ──→ running ──→ completed
  │            ├─────→ failed
  │            └─────→ cancelled
  └──────────────────→ cancelled
```

| 裁决 | 说明 |
|------|------|
| Durable queue owner | **Go + `meta.db.agent_turns` 是唯一 durable queue owner**；host-managed Turn 不在 bridge 再排第二套队列。 |
| 并发边界 | 同一 ChatSession 最多一个 `running` Turn；其余为 FIFO `queued`；queued 尚未进入 1acp runtime。 |
| 唯一终态契约 | 只有匹配 active `turn_id` 的 **`turn_terminal`** 可以驱动 AgentTurn 终态；generic `error`、控制错误和 stale terminal 均不得结束 Turn。 |
| 持久化顺序 | 1acp 先保存 SessionRecord `acpx.turn_results[turn_id]`，再发送 terminal；Go 持久化 meta.db terminal 后再转发给 Browser。 |
| 最终回答 | 从 runtime 中该 `prompt_message_id` 后最后一个用户可见 Agent 文本得出；不以流式 delta 或自然语言猜测替代。 |
| 重连 | Browser 通过 `turn_sync` 恢复同一 `turn_id` 的 active / queued 投影，并按 `event_sequence` 去重。 |
| 重启恢复 | 不自动重放：未下发 queued → cancelled；有 durable runtime terminal 的 running → 对账补齐；其余不可信 running → failed。 |
| 取消 | queued 和 running 都必须显式指定 `turn_id`；stale cancel 不得取消后来启动的 Turn。 |
| 编辑 | 纯前端组合动作：取消旧 Turn 并等待 cancelled → 回填 Composer → 用户再次发送时创建全新 Request / Turn。 |

详细契约与恢复窗口以 [Turn 生命周期闭环 v1.1](../features/turn-model/lifecycle-closure-v1.1.md) 为准；领域审计与 Project Activity 以 [Agent Turn 设计](../features/turn-model/design.md) 为准。

## 3. 领域模型

```
Workspace / 项目（同 id；kind=workforce|project）
  ├── ProjectItem（project_items）
  │     ItemType = task | requirement | bug | discussion
  └── Session（前端/UI 总称）
        ├── ChatSession（sessions）
        │     └── AgentTurn（agent_turns；queued → running → terminal）
        └── TerminalSession（tmux window；无 AgentTurn）
```

| 中文名 | 代号 | 定义 |
|--------|------|------|
| **项目** | 产品名 | 对外称呼；API/类型见 **Workspace** |
| **工作区 / Workspace** | `Workspace`、`workspace_*` | **类型与 API 真名**；= 项目的目录投影，**同一 id** |
| **kind** | `workforce` \| `project` | 落库两档；UI：助理 / 项目 |
| **助理** | UI 文案 | `kind=workforce` 的 Workspace；**文案不改为英文** |
| **ProjectItem** | `project_items` · `ProjectItem` struct | 项目工作项**主实体**（Go/TS 真类型；表已落地） |
| **ItemType** | `type` JSON / ItemType | `task` \| `requirement` \| `bug` \| `discussion` |
| **task（枚举值）** | `ItemType=task` | **仅枚举值**；可执行工作项；**不是表名/主类型名** |
| **Task（弃用别名）** | `type Task = ProjectItem` | 兼容旧代码；**禁止新增引用** |
| **需求 / 缺陷 / 讨论** | requirement / bug / discussion | 不可执行议题类；可被拆成 `task` 或 link 约束 |
| **议题状态** | `issue_state` | `open` \| `closed` |
| **工作流状态** | `status` | pending / queued / running / completed / failed / cancelled / blocked / not_ready … |
| **executor** | `executor` | 通道：`agent` \| `function` \| `human` |
| **assignee** | `assignee` | 通道内对象：AgentType / `user` / function 名 |
| **functionType** | body / DispatchSpec | function 通道注册键；与 assignee 镜像；Labels `fn:` |
| **Reply** | replies | ProjectItem 时间线评论/回写 |
| **Session / 会话** | `Session = ChatSession \| TerminalSession` | 前端/UI 联合类型；持久化必须区分 Agent 对话与 tmux 终端，见 §0.11 |
| **ChatSession / Agent 对话会话** | `sessions` · `ChatSession` | Workspace 内长期、可恢复 Agent 对话；覆盖多个 Turn；`task_id` 只是可空的 ProjectItem 单值软关联 |
| **TerminalSession / 终端会话** | `TerminalSession` · tmux window | Workspace 内终端窗口投影；不进入 `agent_turns`，命令输入不自动创建 Turn |
| **AgentTurn / Turn / 本轮** | `agent_turns` · `AgentTurn` | 一次已提交用户意图到明确终态的可审计因果批次；属于一个 ChatSession，可通过 Events 影响多个 Items，见 §0.11 |
| **Turn 状态** | `queued` \| `running` \| `completed` \| `failed` \| `cancelled` | AgentTurn 专用状态机；generic error 不等于 terminal |
| **ProjectEvent** | `project_events` | 项目事实的一次不可变变更；以 `turn_id` 建立 Turn 与 ProjectItem 的 N:M 关系 |
| **TaskRun** | `task_runs` | task 型 ProjectItem 的一次执行/验收/返工尝试；可通过 `origin_turn_id` 追溯发起 Turn；不等于 Turn |
| **里程碑** | Milestone | 路线图节点 |
| **meta.db** | `~/.1agents/meta.db` | 全局元数据库 |
| **business_ref** | `business_ref` | 域对象绑定：`<ns>:<对象>:<主键>`（远期应用/过渡脚本均可） |

### 易混对照

| 说法 | 正确理解 |
|------|----------|
| 工单 | **弃用** → 说 ProjectItem / 工作项；可执行的叫「task 型条目」 |
| Project vs Workspace | **同一实体**：产品「项目」，类型/API `Workspace` |
| Task 表 | **不存在** → `project_items`；`task` 只是 ItemType |
| Task vs Issue | 旧说「Task=Issue」→ 现为 **ProjectItem + 话题字段**；类型靠 ItemType |
| 助理 vs assistant_text | **助理** = workforce 实体；**assistant_text** = 模型回复气泡 |
| SessionTier / professional-project | **废止为落库概念** → 创建用 `template_project` |
| ChatSession vs Turn | ChatSession 是长期可恢复 Agent 对话容器；Turn 是其中一次提交到终态；一个 ChatSession 有多个 Turn |
| ChatSession vs TerminalSession | 前者由 `sessions` + 1acp runtime 支撑并拥有 Turns；后者是 tmux window / ttyd 终端字节流 |
| Turn vs 前端折叠组 | 新 Turn 以 Go 生成的 `turn_id` 为准；仅无 ID 的旧历史允许按消息边界 fallback |
| Turn vs TaskRun | Turn 表示用户意图因果批次；TaskRun 表示某个 task 型 ProjectItem 的一次执行尝试 |
| ChatSession 与 ProjectItem | `sessions.task_id` 是可空软关联；ChatSession 不因一轮影响多个 Items 而绑定其中任意一个 |

## 8. 协议与会话 ID

| 中文名 | 代号 | 定义 |
|--------|------|------|
| **ACP** | Agent Client Protocol | coding agent ↔ 宿主 |
| **1agents ChatSession ID** | `session_id` · `sessions.id` | Go 生成的 Agent 对话宿主会话 canonical ID；对应 1acp `acpxRecordId`；覆盖多个 Turn；不是终端 tmux window ID |
| **cc_session_id** | — | IM/cc-connect 会话 |
| **acp_session_id** | — | Agent/ACP 侧 resume/load session UUID；不是 `sessions.id` |
| **agent_session_id** | — | Agent 可选的原生线程身份；不是 `sessions.id` |
| **client_request_id** | Browser `requestId` | 一次 Prompt 提交与网络重试的幂等 ID；不是 Turn ID |
| **turn_id** | `agent_turns.id` | Go 生成的 canonical Turn ID；贯穿 Go、bridge、1acp、Reply、ProjectEvent、TaskRun 和 Browser |
| **runtime_request_id** | `requestId=turn_id` | runtime cancel/result/usage 身份；不得由 bridge 另造 |
| **prompt_message_id** | `SessionMessage.User.id=turn_id` | 1acp SessionRecord 中精确的 transcript Turn 边界 |
| **event_sequence** | `sequence` | Turn 内单调事件序号；Browser 用于去重和过滤迟到事件 |
| **Turn 状态同步** | `turn_state` / `turn_sync` | queued/running/terminal 状态与重连后的 durable queue 投影 |
| **Turn 唯一终态** | `turn_terminal` | 唯一可驱动明确 AgentTurn 终态的事件；generic `error` 只表达错误，不隐含终态 |
| **Chat WS** | `/api/agent/chat/ws` | agent 事件流 |
| **终端 WS** | ttyd `/ws` | 终端字节流 |
| **HAPPY_RPC_ADAPTER_ENTRY** | env | adapter 入口 |
| **wire** | envelope | 中转密文封装 |
| **assistant_text** | 消息 kind | **仅**模型回复侧；≠ 助理实体 |

协议恒等式：

```text
sessions.id
  == 1acp acpxRecordId

agent_turns.id
  == Go→bridge turnId
  == runtime requestId
  == SessionMessage.User.id
  == turn_terminal.turnId
```

`client_request_id` 只用于把 Browser optimistic bubble 和网络重试绑定到上述 `agent_turns.id`，不参与 runtime 身份。完整 ID 规则见 §0.11。

## 14. 废弃 / 迁移对照

| 旧称或错误用法 | 现行 |
|----------------|------|
| 表 `tasks` | **`project_items`**（已 rename） |
| 类型名 Task 作主实体 | **`ProjectItem` struct**；`Task` 仅 deprecated alias |
| TaskType | **ItemType**；TaskType deprecated |
| `kind=assistant` | **`kind=workforce`**（落库已 remap） |
| SessionTier / professional-project 作**落库** | **废止**；创建模板 UX = **`template_project`** |
| executor=AIWorkforce | **否决**；`agent\|function\|human` |
| handler / taskapi 各写一套 executor 校验 | **否决**；统一 `meta.NormalizeExecutorAssignment` |
| 「Task 可无 project 行」 | **否决**；始终有 Workspace 行 |
| 把 ChatSession 当一次 Prompt / 一次执行 | **否决**；ChatSession 是覆盖多个 Turn 的长期可恢复 Agent 对话容器 |
| 把 TerminalSession 的命令输入自动当 Turn | **否决**；TerminalSession 是 tmux/ttyd 字节流，除非另有显式 Agent 提交模型 |
| 把 Turn 当纯前端消息折叠组 | **否决**；新 Turn 以 Go `agent_turns.id` 为 canonical 身份；旧历史才允许 fallback |

| bridge 自行生成 runtime `requestId` | **否决**；host-managed Turn 必须 `runtime requestId = turn_id` |
| generic `error` 结束 Turn | **否决**；只有匹配 active Turn 的 `turn_terminal` 可进入终态 |
| backend 重启后自动重放 queued/running Turn | **否决**；外部工具可能非幂等，按 §0.11 恢复策略收口 |
| 编辑旧 Turn 建立 replace/supersedes | **否决**；取消旧 Turn、回填草稿、重新发送创建全新 Request / Turn |
| 工单 | 勿用 |
| 应用 registry 为当前扩展真源 | **否**；过渡 = skill/scripts/浏览器 |
| `html/` | `frontend/` |

## 15. 维护约定

1. 术语冲突以 **§0** 为准；改枚举/表名/校验入口必须同步本表。  
2. **UI 中文「助理」**不随 `workforce` 改文案，除非产品另行决策。  
3. **API/类型保持 `Workspace` + `workspace_*`**，产品文案用「项目/助理」。  
4. **新代码**：只用 `ProjectItem` / `ItemType` / `NormalizeExecutorAssignment`；勿新增 `Task` / `TaskType` 引用。  
5. **Session / Turn 新代码**：先区分 `ChatSession` 与 `TerminalSession`；Agent 对话身份使用 `sessions.id`；Turn 身份只接受 Go `agent_turns.id`；Browser request、ACP session、runtime request 不得互相代用。
6. **Turn 终态**：新增错误或控制事件时必须明确是否为 `turn_terminal`；generic error 默认非终态。
7. **本阶段收尾**：#184 与 M6-1/2（#197/#198）已关闭叙事；可选后续 #199 模板烟测、以及最终删除 `Task` 别名。
