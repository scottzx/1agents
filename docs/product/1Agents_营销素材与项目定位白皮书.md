# 1Agents 营销素材与项目定位白皮书

本文档统一 1Agents 的对外定位、核心话术、目标受众和传播文案。产品事实与完整机制以 [1Agents 项目介绍](./1Agents_项目介绍.md) 为准，领域术语以 [名称定义表](./名称定义表.md) 为准。

---

## 1. 核心定位

### 一句话介绍

**1Agents 是一个开源、自托管的 AI-native 工作操作系统，也是一套面向多智能体协作的 Agent Infra。它把数据、需求、任务、执行、验收和回写连接成一张自循环的智能体 Graph，让一个人也能组织一支持续工作的 AI 团队。**

### 核心表达

> **一万-Agent Infra，是基础设施；自循环智能体 Graph，是工作方式；一人成军，是最终结果。**

### “一万-Agent Infra”是什么意思

“一万-Agent”不是同时运行数量或性能容量的承诺，而是产品对基础设施的要求：

- 可以接入不同类型、不同模型、不同供应商的 Agent；
- Agent 可以升级和替换，项目目标与执行历史不丢失；
- 大量执行节点可以并行、依赖、阻塞、返工和继续推进；
- 所有执行者共享稳定的任务上下文、状态、关系和验收标准；
- 人始终掌握目标、边界、授权和最终责任。

我们销售的不是“更多聊天窗口”，而是让大量执行者围绕同一张工作图协作的能力。

---

## 2. 我们在解决什么问题

传统 AI 助手擅长完成一次问答，却很难独立管理一件工作的完整生命周期：

- 信息散落在聊天、邮件、IM、文档、日历和数据系统中；
- 需求、反馈、任务、会话和最终产物彼此割裂；
- 每一步都需要人复制上下文、选择工具并唤醒下一个 Agent；
- 多个 Agent 同时工作时，缺少统一的依赖、状态和验收事实；
- 执行完成后，结果没有回到计划，下一轮仍然从头解释；
- 失败、阻塞和返工隐藏在聊天记录里，无法形成可追踪的项目状态。

1Agents 解决的不是“如何让 Agent 再回答一次”，而是：

> **一件工作进入系统后，如何持续走到被验证完成。**

---

## 3. 核心工作方式：Graph，而不只是 Loop

Loop 只能说明“执行一次，再来一次”。真实工作还需要表达：

- 哪些对象正在被处理；
- 当前分别处于什么状态；
- 谁依赖谁，哪些任务可以并行；
- 什么条件满足后才能继续；
- 验收通过或失败后应该走向哪里；
- 执行结果如何改变后续计划。

因此，1Agents 用工作 Graph 组织协作：

| Graph 元素 | 产品含义 |
| --- | --- |
| **节点 Node** | 数据、Inbox 项、需求、缺陷、功能点、任务、里程碑、会话、产物、验收记录 |
| **状态 State** | 待整理、已规划、待执行、执行中、阻塞、待验收、已完成、需返工 |
| **边 Edge** | 来源、归属、依赖、拆解、分发、关联、验收、回写 |
| **判断 Decision** | 是否满足依赖、由谁执行、验收是否通过、下一步走向哪个节点 |
| **回流 Feedback** | 将结果、失败原因和用户反馈写回 Graph，更新计划并触发后续节点 |

**Loop 是 Graph 中的一条回路；Graph 才能表达完整工作。**

---

## 4. 端到端业务 Graph

1Agents 将真实业务链路连接为：

```text
数据源
  → 数据治理与 Python/function 热更新
  → Inbox 分类与意图识别
  → 提取真实用户需求 / 反馈 / 缺陷
  → 创建项目工作项
  → 纳入任务蓝图
  → 拆解待办、依赖与里程碑
  → Schedule 定时与任务调度
  → 1ACP / ACPX 分发
  → Agent / function / human 执行
  → Check 验收
  → 通过则关闭，不通过则返工
  → 状态、结果和经验回写任务蓝图
```

这条链路让信息不只“被收集”，而是逐步变成可执行、可验证、可回写的工作。

---

## 5. 任务蓝图：产品的核心工作地图

传统任务清单只回答“还有什么没做”。任务蓝图还要回答：

- 这项工作来自哪条数据、哪位用户、哪个需求或缺陷；
- 它属于哪个项目、模块、功能点和里程碑；
- 它依赖谁、阻塞谁，又会触发哪些后续任务；
- 它当前处于规划、执行、阻塞、验收、完成还是返工；
- 它由哪个 Agent、function 或 human 负责；
- 它的验收标准、过程记录和完成证据在哪里。

当前产品中的“功能蓝图”负责展示模块、功能点、来源需求、交付任务、目标版本和交付状态；任务、看板、日历和里程碑则从不同角度消费同一张工作 Graph。

任务蓝图不是又一个待办页面，而是规划、调度、验收和项目事实的共同索引。

---

## 6. 1ACP：可替换的多智能体执行层

1Agents 通过 1ACP / ACPX 接入 Codex、Claude Code、Pi、OpenClaw 和其他 ACP-compatible Agent。

协议层负责传递工作目录、项目上下文、任务说明、验收标准、会话状态、权限、工具事件和最终结果。执行者可以升级和替换，但工作 Graph 中的目标、依赖、状态和历史保持稳定。

这让产品从“绑定某个模型的 AI 工具”变成“可以持续接入新执行者的 Agent Infra”。

---

## 7. 三类执行者

不是所有节点都应该交给大模型。1Agents 在同一个任务内核中调度三类执行者：

| 执行者 | 适合的工作 | 人的感受 |
| --- | --- | --- |
| **Agent** | 研究、规划、代码实现、分析、创作和需要判断与变通的任务 | 不需要逐步教它点击哪个按钮，但可以查看过程和结果 |
| **function** | 数据处理、同步、构建、测试、格式转换等固定、确定、可复现步骤 | 稳定、低成本、容易验证 |
| **human** | 目标定义、价值判断、高风险授权、取舍和最终验收 | 人不被排除，而是回到真正需要负责的节点 |

三类执行者共享任务描述、上下文、状态、权限、验收标准和时间线，因此可以顺畅接力。

## 8. 目标受众

### 核心用户

- 同时推进多个产品、客户或内容项目的独立开发者；
- 需要一个人承担产品、研发、运营和交付的单干创始人；
- 处理大量信息流、研究任务和交付节点的自由职业者与知识工作者；
- 希望把 Codex、Claude Code 等工具从单次使用升级为持续工作系统的人；
- 需要自托管、真实工作区、可追溯执行和人工控制的团队。

### 用户想要的不是

- 再多一个聊天机器人；
- 一套只能展示任务、不能推动任务的看板；
- 一个完全失控、无法验收的“全自动 AI 公司”；
- 每增加一个 Agent 就增加一套孤立上下文。

### 用户真正获得的

- 信息有统一入口；
- 需求和反馈可以进入项目；
- 复杂目标可以逐层拆解；
- 任务可以被调度和分流；
- 多个执行者共享事实；
- 失败和阻塞显式可见；
- 结果有验收、有证据、能回到计划；
- 人只在真正需要判断的节点介入。

## 9. 对外传播统一口径

### 推荐使用

- 一万-Agent Infra
- 自循环智能体 Graph
- AI-native 工作操作系统
- 多智能体协作基础设施
- 任务蓝图
- 从数据进入到验收回写
- Agent / function / human 三类执行者
- 一个 Agent 可以做一步，一张 Graph 才能把事情做完
- 一人成军 / One Person, Infinite Agents

### 避免单独使用

- “AI 原生办公软件”：范围过宽，不能体现 Graph 和执行基础设施；
- “AI 项目管理工具”：容易被理解为只做看板和排期；
- “多个 Chatbot 放在一起”：无法表达任务内核、调度和验收；
- “完全自动、无需人类”：违背 human 最终责任和授权边界；
- “保证同时运行一万个 Agent”：把产品定位误解为容量指标；
- “所有任务都必须绑定需求或缺陷”：与轻量 workforce 和现行 ProjectItem 规则不一致。

## 10. 可直接使用的传播文案

### 10.1 产品短介绍

> 1Agents 是一套面向多智能体协作的 Agent Infra。它把数据源、Inbox、需求、任务蓝图、Schedule、1ACP、Agent 执行和 Check 验收连接成一张自循环工作 Graph，让工作可以从进入系统一路走到被验证完成。

### 10.2 X / Twitter / Hacker News 风格

> One agent can complete a step. A work Graph can complete the job.
>
> 1Agents is an open-source, self-hosted Agent Infra for people running many projects with Codex, Claude Code, and other agents.
>
> Data → Inbox → requirements → task blueprint → Schedule → 1ACP → execution → verification → write-back.
>
> Executors are replaceable. Goals, dependencies, state, and evidence stay in the Graph.
>
> One Person, Infinite Agents.

### 10.3 小红书 / 微信朋友圈风格

> **我不想再“带”一群 AI 助手了，我想让它们围绕同一张工作图协作。**
>
> 所以我们做了 1Agents：
>
> 1. 数据、消息和想法先进入 Inbox；
> 2. 系统识别需求、反馈和缺陷，分发到项目；
> 3. 任务蓝图把需求、功能点、任务、依赖和里程碑连起来；
> 4. Schedule 通过 1ACP 把执行点交给 Codex、Claude Code 等 Agent；
> 5. 完成后自动或人工验收，不通过就带着原因返工；
> 6. 所有结果回到蓝图，成为下一轮行动的上下文。
>
> 不是多几个聊天框，而是搭一套一万-Agent Infra。
>
> **自循环智能体 Graph，是工作方式；一人成军，是最终结果。**
