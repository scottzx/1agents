# PRD：Agents 圆桌脑暴 MVP

**Status:** 已定稿  
**Date:** 2026-07-23  
**设计详稿:** [design.md](./design.md)  
**执行人:** grok-build  

---

## 问题

复杂软硬件产品议题需要多职能视角碰撞；单 Agent 易自洽、缺对立。需要可审计的「圆桌」而不是黑盒长推理。

## 方案（一句话）

固定 3 轮剧本 + 6 个真实 Grok Build session（裁判 + 市场/产品/研发/运营/财务），tmp 隔离，R3 用 1acp resume；UI 默认只展示发言正文。

## 用户故事

1. 作为产品负责人，我从发现中心打开「Agents 圆桌」，与裁判澄清议题后，看到五职能各两轮观点与裁判终稿。  
2. 作为用户，我不想被 tool 过程淹没，默认只读正文。  
3. 作为 IT 软硬件决策者，我需要研发席明确可行性与风险，并与产品席可区分。

## 验收

见 [design.md §7](./design.md#7-acceptance-ship-criteria)。成功标准：**功能可演示跑通 3 轮**。

## 不做

开放拓扑、多二进制混排、执行闭环、投票、无限轮。
