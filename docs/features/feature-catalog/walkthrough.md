# 功能蓝图、甘特图与导出操作指南

本文面向项目负责人和验收人员，说明如何启用功能蓝图、建立需求到任务的追溯关系、查看甘特图，以及导出可复用的报告数据。

## 1. 启用或关闭功能蓝图

1. 打开目标项目，进入“设置”。
2. 开启“启用功能蓝图”。
3. 回到任务管理，确认顶部视图切换器出现“功能蓝图”。

该开关只控制入口和 AI PM 工作流，不删除模块、功能点或关联数据。关闭时，如果当前位于功能蓝图，界面会回到任务视图；重新开启后，原蓝图应完整恢复。

旧项目和轻量任务项目默认关闭功能蓝图，可继续使用“需求 → 任务”的原有流程。

## 2. 建立模块树

1. 进入“功能蓝图”，点击“+ 一级模块”。
2. 选中模块后，可继续添加二级模块、三级模块或功能点。
3. 在右侧详情中编辑名称、说明和同级顺序。
4. 功能点必须是叶子节点；系统会拒绝第四级模块、循环移动和跨项目父节点。

桌面端同时显示树和详情。窄屏下先显示单列树，点选节点进入详情，并使用顶部返回操作回到树。

## 3. 建立追溯关系

选中功能点后，在详情中完成以下关联：

- “来源需求/缺陷”：说明为什么要建设该功能。
- “交付任务”：说明哪些任务实现该功能。
- “目标版本”：选择一个由 SemVer bump 创建的 `x.y.z` 里程碑。

功能点会根据交付任务显示“未拆解、待开始、进行中、已交付或需要重新规划”。模块会聚合后代功能点的覆盖率、任务进度和目标版本分布。

如功能点目标版本与已关联任务的里程碑不一致，可先预览差异，再确认同步。同步只更新关联任务，不修改历史自由命名里程碑。

## 4. 使用 AI PM

- 蓝图为空时，点击“与 AI PM 一起生成”，让 AI PM 从当前需求生成模块、功能点和追溯关系。
- 蓝图已有内容时，同一入口用于维护现有结构。
- 选中功能点后，可让 AI PM 将该功能点拆解为任务，并把新任务关联回功能点。

AI PM 会先读取 `.1agents/project_config.json`。只有顶层 `featureCatalogEnabled` 为 `true` 时，才允许写入功能蓝图；关闭时继续轻量需求拆解流程，不创建隐藏蓝图数据。

## 5. 查看甘特图

1. 在功能蓝图顶部切换到“甘特图”。
2. 甘特图按模块路径分组，模块可折叠。
3. 使用“日 / 周 / 月”切换时间粒度。
4. 点击任务条或任务名称进入原任务详情。
5. 依赖线来自任务 `DependsOn`；版本菱形来自 SemVer 里程碑目标日期。
6. 没有完整 `PlannedStart` / `PlannedEnd` 的任务显示在“未排期任务”区。

模块不保存自己的计划日期。模块开始时间始终是后代任务的最早 `PlannedStart`，结束时间始终是后代任务的最晚 `PlannedEnd`。编辑任务日期并重新打开甘特图后，模块日期和进度会从任务事实重新计算。

## 6. 导出报告

功能蓝图顶部提供两个导出按钮：

- “导出 Markdown”：保留一级、二级、三级模块结构，并列出功能点说明、来源需求/缺陷、交付任务、目标版本和进度状态。
- “导出 JSON”：生成可被程序重新消费的完整蓝图。

JSON 顶层契约固定为：

```json
{
  "schemaVersion": 1,
  "catalog": {
    "nodes": [],
    "links": []
  },
  "items": [],
  "gantt": {
    "modules": [],
    "unscheduled": [],
    "milestones": []
  }
}
```

`catalog` 保存模块、功能点和追溯边；`items` 保存关联需求、缺陷和任务的稳定字段；`gantt` 是由任务日期、依赖、状态和版本里程碑派生的只读投影。模块对象只包含 `aggStart` / `aggEnd`，不会出现第二套 `plannedStart` / `plannedEnd`。

## 7. 验收检查清单

- 开关关闭后入口隐藏，数据仍在；重新开启后数据恢复。
- 一级、二级、三级模块和功能点均能创建、移动和排序。
- 来源需求、交付任务和目标版本可追溯。
- 修改任务日期后，甘特图模块日期同步更新。
- 无完整计划日期的任务进入“未排期任务”。
- 点击甘特图和版本树中的任务，仍进入原任务卡片并保留原操作。
- legacy milestone 及其任务关联不变。
- Markdown 和 JSON 导出均可下载，JSON 的 `schemaVersion` 为 `1`。

## 8. 发布前命令

从仓库根目录执行：

```bash
git diff --check
(cd backend && go test ./...)
(cd frontend && yarn check && yarn build)
```

以上检查全部通过后，才可完成 0.5.0 验收任务。
