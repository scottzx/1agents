# 功能蓝图优化 0.1.0

## 目标

在不破坏现有功能蓝图数据和接口的前提下，交付以下能力：

1. 模块目录从最多三级扩展为最多九级，功能点保持叶子语义。
2. 桌面端支持模块和功能点的完整树拖拽，移动后自动持久化父子关系与顺序。
3. 模块树支持按项目会话折叠和展开，筛选时自动展示命中路径。
4. 用户可以手动保存功能蓝图历史版本、设置别名、分页查看和删除。
5. 恢复历史版本前自动保存“恢复前”安全版本；恢复过程原子、幂等，并报告失效的外部关联。

看板归口：`#311 优化功能蓝图：九级目录、完整拖拽与历史版本`  
目标里程碑：`0.1.0`（ID：`463f9b87fb4caa2f4a73606262e8b596`）

## 已确认的产品决策

- 根模块是第 1 级，最多第 9 级；功能点不占模块层级。
- 桌面端使用原生 HTML Drag and Drop；移动端和键盘继续使用父模块选择与上移/下移。
- 搜索、状态或版本筛选生效时禁用拖拽。
- 模块默认展开，折叠状态只保存在当前 Web 会话内。
- 历史版本只覆盖功能蓝图节点、描述、顺序、目标版本和 source/delivery 关联，不备份项目事项正文。
- 历史版本数量不限，列表按 50 条游标分页。
- 只有恢复接口要求请求幂等；手动连续保存允许产生多个版本。
- 历史版本仅由 Web UI 管理，不新增 CLI、MCP 或 AI 保存/恢复工具。
- 复用现有语义化里程碑 `0.1.0`。

## 验收摘要

- 可以创建 1–9 级模块并在第 9 级下创建功能点，第 10 级在所有写入路径中被拒绝。
- 根模块可以拖到另一个模块内或拖回根目录，刷新后父子关系和顺序保持正确。
- 保存版本后修改蓝图，再恢复版本，可准确还原目录、说明、顺序、目标版本和有效关联。
- 恢复操作只生成一次“恢复前”版本；相同请求重试不会重复恢复或重复写审计事件。
- 已删除或跨项目的任务、需求、缺陷和里程碑引用不会破坏恢复，系统会跳过或清空并报告。
- 后端全量测试、前端类型检查、构建、目标单测和人工浏览器验收通过。

## 非目标

- 不实现触摸拖拽或新的键盘拖拽模式。
- 不实现自动定时存档、每次 AI 修改自动存档、版本 diff/merge 或部分恢复。
- 不备份或回滚任务、需求、缺陷和里程碑正文。
- 不新增跨标签页实时同步或新的协作冲突协议。
