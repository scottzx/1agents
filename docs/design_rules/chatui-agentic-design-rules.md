# Chat UI Agentic Design Rules

本规范定义当前 1Agents Chat UI 的整体设计风格与实现约束，适用于 `frontend/src/components/chat/*` 与相关 chat 样式。目标是让智能体对话既像自然聊天，又像可审计的开发工作流。

## 1. 设计定位

Chat UI 采用 **Agentic UI / Thought Process Visualization** 风格：

- 对用户展示智能体的关键执行过程，但默认不打断阅读。
- 对话主线只保留用户问题与助理最终结论。
- 思考、工具调用、中间说明、权限确认等过程信息折叠进同一轮的过程块。
- 视觉上避免传统左右大气泡聊天感，更接近文档流 + 轻量终端工作台。

关键词：

- Agentic UI
- 思考过程可视化
- Human-in-the-loop
- Developer-centric aesthetic
- Minimal document flow
- Web Terminal Lite

## 2. 布局原则

### 2.1 文档流优先

助理回复应以通栏文档流阅读为主，而不是强气泡。

- Assistant 消息使用左侧细边线，而不是厚重卡片。
- User 消息可以保持轻量气泡，但颜色应克制，不使用高饱和实心强调色。
- 消息区背景使用柔和白色，不使用偏黄乳白，也不使用明显浅灰。
- 大段内容应靠排版层级区分，而不是依赖多层嵌套卡片。

### 2.2 通栏过程块

智能体执行过程使用接近全宽的折叠过程块。

- 过程块最大宽度接近消息列表宽度。
- 标题行是轻量状态行，不应像弹窗、Alert 或大卡片。
- 展开内容中允许展示工具行、参数、输出、diff、权限确认。
- 一个 turn 内的过程信息应合并到同一个过程块中。

## 3. Turn 合并规则

一轮 turn 指从一条 user 消息开始，到下一条 user 消息之前的所有内容。

### 3.1 默认外露内容

每轮 turn 默认只外露：

- user query
- 助理最后一条正式回答

### 3.2 默认折叠内容

同一轮中的以下内容应折叠进过程块：

- thinking
- tool use
- tool result
- permission request
- 助理中间过程说明

例如：

```text
我会创建一个临时文件...
测试文件已经创建...
文件修改完成...
已完成工具调用测试：
...
```

应展示为：

- 过程块：包含前三段过程说明与工具调用记录
- 外露回答：只保留“已完成工具调用测试：...”

### 3.3 历史回放要求

`loadHistory` 后也必须应用同样的 turn 合并规则。

- 不依赖实时事件状态。
- 不依赖时间戳。
- 不要求后端新增字段。
- 以前散落的过程文本、工具调用和工具结果都应在前端重组为单个过程块。

## 4. 过程块规范

### 4.1 折叠标题

过程块标题应总结执行事实，而不是只写“工具调用”。

推荐格式：

```text
读取 5 个文件，运行 8 条命令，使用 6 个工具
```

英文：

```text
Read 5 files, ran 8 commands, used 6 tools
```

如果包含 thinking：

```text
思考 2 次，读取 5 个文件，运行 8 条命令，使用 6 个工具
```

### 4.2 完成态

完成后的过程块显示轻量状态：

```text
已处理
```

注意：

- 不显示耗时，除非后续明确有可靠 turn start/end 数据。
- 不使用“已处理 xx 秒”这类需要时间戳或前端冻结状态的文案。
- 不新增“过程说明”标签，避免额外视觉层级。

### 4.3 展开内容

展开后保持原有工具组样式：

- thinking 使用原 thinking 行样式。
- tool call 使用原工具行样式。
- 中间助理文本直接作为普通 Markdown 内容放入过程组，不额外加标题。
- permission 继续使用现有 Human-in-the-loop 控件样式。

## 5. Markdown 渲染规范

### 5.1 User 与 Assistant 共用 Markdown 渲染

User query 与 Assistant answer 都应支持 Markdown。

- 使用同一个 Markdown renderer。
- 使用同一套 chat Markdown CSS。
- 支持列表、代码块、链接、任务引用、表格、Mermaid。
- 排队中的 user query 可以保持纯文本单行省略，避免队列布局被撑开。

### 5.2 Chat Markdown 标题尺度

聊天中的 Markdown 标题不应使用完整文档的大标题尺度。

推荐：

- 正文：`14px`
- 行高：约 `1.68`
- h1：约 `1.16em`
- h2：约 `1.1em`
- h3：约 `1.04em`
- h4-h6：约 `1em`

要求：

- h1/h2 不显示文档式下划线分割线。
- 标题更像段落标题，而不是页面标题。
- 标题与段落之间保持紧凑间距。
- 列表、代码块、表格保留清晰层级，但不应造成大面积跳动。

## 6. 视觉规范

### 6.1 背景

Chat 区域背景应是柔和白色：

- 不用偏黄乳白。
- 不用明显浅灰。
- 不用纯白大面积刺眼铺底。

当前推荐：

```css
--chat-bg-page: #fbfcfd;
--chat-bg-panel: rgba(255, 255, 255, 0.9);
--chat-bg-card: #ffffff;
```

暗色模式应回落到全局 dark token，不应被浅色 chat token 污染。

### 6.2 色彩

整体克制、技术工作台风格。

- 主色只用于链接、状态、少量强调。
- 过程块使用边框、浅底、mono 信息密度建立层级。
- 不使用大面积渐变、装饰性光斑、强营销感色块。
- 避免整屏偏单一暖色、紫色或深蓝。

### 6.3 圆角与边框

- 卡片/过程块圆角保持小半径，建议 `6px-8px`。
- 不使用过大的 pill/card 圆角。
- 分隔依赖细边框、虚线边框、左侧细线。

### 6.4 字体

- 正文使用产品全局 sans。
- 工具名、参数、命令、路径使用 mono。
- 不通过夸张字号制造层级。
- 不使用负 letter-spacing。

## 7. 工具与终端信息

### 7.1 工具行

工具行应保持可扫描：

- 状态图标
- 工具类型图标
- 工具名 badge
- 关键参数摘要
- 展开 caret

### 7.2 参数与输出

- 参数名使用 mono badge。
- 长参数、对象参数使用 pre block。
- 命令类工具使用轻量终端块。
- 输出保持可复制、可滚动、不过度装饰。

### 7.3 文件与 Diff

- 文件路径使用 mono chip。
- diff 保持原有 add/del 语义色。
- 不把文件路径做成大按钮或显眼卡片。

## 8. Human-in-the-loop 权限确认

权限确认是 Agentic UI 的核心交互之一。

要求：

- 权限请求必须在对应过程块中可见。
- 有 pending permission 时，过程块应自动展开或保持可发现。
- 按钮语义清晰：拒绝、总是拒绝、允许、总是允许。
- 权限完成后保留轻量决策回执。
- 不把权限请求隐藏在最终回答之后。

## 9. 交互行为

### 9.1 折叠默认值

- 正在执行的当前过程块可以展开。
- 已完成的历史过程块默认折叠。
- 用户手动展开/折叠应尽量保持状态。

### 9.2 Auto-follow

消息列表自动滚动只应在用户贴近底部时发生。

- 用户正在点击/选择/滚动时，不应强制拉到底部。
- 流式输出不应吞掉用户点击折叠标题的行为。

### 9.3 排队消息

排队中的 user query 保持单行省略。

- 可取消。
- 不参与 Markdown 块渲染。
- 不撑高消息列表。

## 10. 不做什么

以下做法不符合当前 Chat UI 方向：

- 把每次工具调用都渲染成大卡片。
- 把中间助理说明全部外露，导致一轮回复像多条正式回答。
- 用 H1/H2 的文档标题尺度渲染聊天内容。
- 给过程说明新增显眼标签，如“过程说明”。
- 为没有可靠数据的历史 turn 强行显示耗时。
- 用高饱和用户气泡或大面积品牌色主导对话区。
- 在聊天主流程里使用营销页式 hero、插图或装饰背景。

## 11. 验收清单

实现或修改 Chat UI 后，应检查：

- 一轮 turn 中只外露最后一条助理正式回答。
- 中间助理叙述、thinking、tool use/result、permission 都在同一个过程块内。
- loadHistory 后仍能正确合并历史 turn。
- User query 支持 Markdown 渲染。
- Assistant answer 标题字号不突兀。
- 排队 user query 仍是单行省略。
- 已完成过程块默认折叠并显示“已处理”。
- 权限请求不会被折叠到用户难以发现的位置。
- `yarn check` 通过。
- 前端构建可通过 `yarn build`。
