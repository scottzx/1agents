THE PROBLEM

AI 很会完成一步，
却很难持续交付一件事。

当前的编码 Agent 通常围绕一次会话优化。真正的软件项目却需要跨越计划、依赖、执行、验证、返工和长期上下文。

01

上下文割裂

不同模型、不同会话和不同项目之间缺少稳定的任务事实，人需要反复复制背景、解释进度。

02

能力与成本错配

规划、编码、审查对模型能力的要求不同，但团队往往让同一个模型包办所有阶段。

03

执行没有闭环

结果散落在聊天、终端和文件里。任务是否真的完成、谁来验收、失败后去哪里返工并不清楚。

THE 1AGENTS WAY

一张工作 Graph，
多种专业执行者。

Agent Profile 定义角色、模型、权限和工作方式；工作 Graph 保存目标、依赖、状态、产物和验收标准。

01 PLAN

制定计划

强推理模型理解目标，拆分需求和依赖，生成可验证的任务。

02 ROUTE

分配 Profile

根据任务阶段、能力、成本和权限，选择合适的 Agent。

03 EXECUTE

真实环境执行

Agent 在工作区内使用文件、终端、Git 和工具完成交付。

04 REVIEW

独立模型复审

另一角色检查实现、测试与风险，决定通过或携带原因返工。

05 ACCEPT

人工关键验收

人在真实设备、权限和产品判断节点承担最终责任。

STABLE CORE

执行者可以增加，模型可以替换，工作事实保持稳定。

HUMAN CONTROL

自动化不是取消人，而是把人留在最需要判断的位置。

BUILDING WITH AWS

从本地工作台，
走向可信的云端 Agent 控制面。

AWS 不是一张服务清单，而是 1Agents 从创始人自用走向团队协作、弹性执行和可审计运营的基础。

01
AGENT RUNTIME

隔离、可扩展的 Agent 执行环境

评估 Amazon Bedrock AgentCore Runtime、Gateway 与 Identity，让不同 Agent 获得独立运行环境、受控工具入口和工作负载身份。

查看 AWS 官方能力 ↗
02
ORCHESTRATION

事件驱动的任务调度与人工闸门

使用 Step Functions 协调长流程与人工回调，结合 EventBridge 和 SQS 解耦任务事件、重试与执行队列。

查看 AWS 服务集成 ↗
03
MODEL ROUTING

质量、能力与成本感知的模型路由

评估 Amazon Bedrock 的模型访问和智能 Prompt Routing，同时保留 1Agents 基于任务阶段与 Profile 的应用级路由。

查看 Prompt Routing ↗
04
TRUST & OBSERVABILITY

从模型调用到交付结果的完整证据链

将会话、工具调用、任务状态、Token 成本、审查结果和人工决定连接起来，借助 CloudWatch 建立运行与质量观测。
